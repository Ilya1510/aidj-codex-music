# Пробный DJ-микс

`aidj.dj_preview` собирает отдельный MP3 для прослушивания идеи режима «Волейбол DJ».
Приложение, принадлежность песен плейлистам и исходные файлы не меняются.
Это экспериментальная подготовка микса; автоматический режим в APK пока не включён.

## Что делает

- Берёт ограниченную подборку из Volleyball, исключая последний дизлайк владельца.
- Учитывает сохранённые пользователем границы воспроизведения.
- Через librosa оценивает темп, удары, повторяемость и энергию. Фазу такта оценивает
  по акцентам. Это эвристика, а не распознавание куплетов/припевов нейросетью;
  правильность музыкальных границ нужно оценивать на слух.
- Предлагает несколько непрерывных фрагментов на 88–132 секунды, кратных восьми тактам.
- По отдельному плану меняет темп не более чем на 3% с сохранением высоты тона.
  Длительность рассчитывает по числу долей и целевому темпу, включая замедление.
- Внутри группы с одинаковым темпом сводит восемь долей и передаёт бас между
  композициями в середине перехода. При смене группы использует короткий переход.
- Выравнивает громкость, ограничивает пики и пишет таймкоды фактически полученного микса.
- Дополнительно делает короткий файл только с участками вокруг переходов.

## Запуск

Нужны FFmpeg и отдельное Python-окружение с `requirements-dj.txt`. Основное окружение
бота менять не требуется. Можно использовать готовый FFmpeg из `imageio_ffmpeg`.

Рабочий каталог держи вне Git: там находятся аудио, личная подборка и пути Диска.
В `candidates.json` положи массив пар `["Исполнитель", "Название"]`, от 2 до 16 песен.

```bash
python -m aidj.dj_preview prepare --work "$DJ_WORK"
python -m aidj.dj_preview analyse --work "$DJ_WORK" --ffmpeg "$DJ_FFMPEG"
python -m aidj.dj_preview render --work "$DJ_WORK" --ffmpeg "$DJ_FFMPEG"
```

Первый шаг можно запускать штатным Python бота, два остальных — Python из отдельного
окружения. Перед обработкой проверь свободный диск. Каждый этап запускай отдельно
с ограничением памяти 1 ГБ, TasksMax=64, Nice=10 и таймаутом до 10 минут; на cgroup v1
используй также MemoryLimit=1G. Анализ и рендер идут последовательно, по одной песне.
Исходники ограничены суммой 256 МБ, рендер — максимум 12 композициями.

После анализа создаётся `analysis/<md5>.json`. Выбери варианты фрагментов в `plan.json`:

```json
{"tracks": [{"md5": "…", "targetBpm": 126, "segment": 0}, {"md5": "…", "targetBpm": 126, "segment": 1}]}
```

`md5` берётся из `sources.json`, `segment` — индекс в `segments` результата анализа.
Одинаковый `targetBpm` у соседей включает сведение в ритм. Разный — короткую смену.
После прослушивания можно задать в записи `sourceStart`, `sourceEnd` и исходный
`sourceBpm`: это сохраняет окончание вокальной фразы, даже если оно выходит за
автоматическую сетку. `transitionBeats` у входящей песни меняет длину сведения.
Ручные границы пользователя по-прежнему ограничивают такой исправленный фрагмент.
Полный микс, файл переходов и `tracklist.txt` можно отправить владельцу для оценки;
не добавляй их автоматически в общую разметку или плейлисты.

Для повторной сборки сохраняются исходники, варианты фрагментов и план. После оценки
временные PCM-клипы и отдельное окружение можно убрать по их конкретным путям.

## План интерфейса приложения

В APK 0.12.0 добавлен режим DJ. Пробный MP3 остаётся отдельным артефактом для
сравнения звучания; приложение играет исходные песни двумя независимыми декодерами.

- Под кнопками плейлиста — «Воспроизведение». Обычный, плавный и DJ-режимы
  запоминаются отдельно для каждого плейлиста на устройстве.
- «Покороче / Обычно / Подольше» — мягкие цели 80 / 110 / 140 секунд. Плеер
  берёт ближайший подготовленный фрагмент, а не режет песню по таймеру.
- В очереди остаются отдельные песни. Скип, удаление из очереди и управление
  с экрана блокировки работают в DJ-режиме. «Доиграть полностью» убирает
  автоматический фрагмент только у текущего элемента очереди.
- Сохранённый вручную фрагмент приоритетнее DJ. Оригиналы и скачанные файлы
  не переписываются и повторно на телефон не загружаются.
- Новая шафл-очередь подбирает соседей по близости темпа внутри уже
  отфильтрованного списка. Обычный запуск и ручной порядок очереди сохраняются.
  Соседние совместимые песни получают общий темп с отклонением до 3%; без
  подходящего общего темпа плеер сохраняет разные темпы и делает переход
  с наложением. Это не точное сведение профессионального DJ-контроллера:
  запуск двух MediaPlayer имеет дискретность таймера около 50 мс.
- Следующая песня подготавливается заранее. Наложение — до четырёх ударов,
  ограничено свободным местом после вокальной фразы; кривые громкости имеют
  запас от перегрузки. Если следующая дорожка запоздала, автоматический
  фрагмент отменяется и текущая песня продолжает играть целиком.

## Автоматическая подготовка

При включении DJ приложение отправляет владельческий `POST /api/dj` со списком
ID песен. Это постановка в очередь, без загрузки музыки на телефон. Отдельный
`aidj-dj-prepare.service` последовательно получает с Диска одну исходную песню,
анализирует и удаляет временную копию. Исходники до 40 МБ / 10 минут, декодирование
ограничено первыми 250 секундами; один анализ ограничен 240 секундами. Прогресс
можно посмотреть в настройках DJ: сколько песен имеет подходящие фрагменты.

`aidj.dj_worker` оценивает ритм по спектральным атакам; CPU-модель
[faster-whisper](https://github.com/SYSTRAN/faster-whisper) (`base`, int8) даёт
границы распознанных слов. Правила ищут достаточно широкий промежуток между
распознанными словами. Неразборчивые слова занимают своё время и не превращаются
в мнимую паузу. Окончание фразы важнее точного попадания в удар. Если надёжного
промежутка или темпа нет, результат содержит пустой список — песня играет целиком.
Распознавание пения может ошибаться; автоматическая разметка не означает проверку
на слух. LLM/API для анализа не вызывается, аудио сторонним сервисам не отправляется.

В `bot.sqlite → dj_analysis` хранятся MD5 оригинала, очередь обработки и небольшая
числовая разметка. Копия разметки входит в каталог приложения и остаётся доступной
офлайн; таблица также входит в часовой бэкап на Яндекс Диске. Тексты распознавания
не сохраняются. Модели лежат в `$AIDJ_STATE_DIR/dj-models` и могут быть скачаны заново.

Для отдельного CPU-окружения, после обычной настройки сервера:

```bash
python3 -m venv .dj-venv
.dj-venv/bin/pip install -r requirements-dj-runtime.txt
sudo .venv/bin/python deploy/install_services.py --user music --install
sudo systemctl enable --now aidj-dj-prepare.service
```

Установщик не включает этот необязательный сервис автоматически. В unit выставлены
MemoryMax/MemoryLimit=1G, TasksMax=64, Nice=10 и низкий приоритет I/O; на cgroup v1
MemoryLimit обеспечивает реальный предел. Один дочерний процесс на песню очищает
память декодера и модели после завершения. На время тяжёлых сборок/диагностики
сервис следует остановить. После превышения лимита памяти сервис сам не перезапускается: сначала нужна диагностика. Анализ работает отдельно от блокировки редактирования
плейлистов и не меняет оценки, доставки в приложение или сами плейлисты.
