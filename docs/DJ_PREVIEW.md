# Пробный DJ-микс

`aidj.dj_preview` собирает отдельный MP3 для прослушивания идеи режима «Волейбол DJ».
Приложение, принадлежность песен плейлистам и исходные файлы не меняются.
Это экспериментальная подготовка микса; автоматический режим в APK пока не включён.

## Что делает

- Берёт ограниченную подборку из Volleyball, исключая последний дизлайк владельца.
- Учитывает сохранённые пользователем границы воспроизведения.
- Через librosa оценивает темп, удары, повторяемость и энергию. Фазу такта оценивает
  по акцентам. Это эвристика, а не распознавание куплетов/припевов нейросетью;
  правильность музыкальных границ нужно оценивать на слух.
- Предлагает несколько непрерывных фрагментов на 88–132 секунды, кратных восьми тактам.
- По отдельному плану меняет темп не более чем на 3% с сохранением высоты тона.
  Длительность рассчитывает по числу долей и целевому темпу, включая замедление.
- Внутри группы с одинаковым темпом сводит восемь долей и передаёт бас между
  композициями в середине перехода. При смене группы использует короткий переход.
- Выравнивает громкость, ограничивает пики и пишет таймкоды фактически полученного микса.
- Дополнительно делает короткий файл только с участками вокруг переходов.

## Запуск

Нужны FFmpeg и отдельное Python-окружение с `requirements-dj.txt`. Основное окружение
бота менять не требуется. Можно использовать готовый FFmpeg из `imageio_ffmpeg`.

Рабочий каталог держи вне Git: там находятся аудио, личная подборка и пути Диска.
В `candidates.json` положи массив пар `["Исполнитель", "Название"]`, от 2 до 16 песен.

```bash
python -m aidj.dj_preview prepare --work "$DJ_WORK"
python -m aidj.dj_preview analyse --work "$DJ_WORK" --ffmpeg "$DJ_FFMPEG"
python -m aidj.dj_preview render --work "$DJ_WORK" --ffmpeg "$DJ_FFMPEG"
```

Первый шаг можно запускать штатным Python бота, два остальных — Python из отдельного
окружения. Перед обработкой проверь свободный диск. Каждый этап запускай отдельно
с ограничением памяти 1 ГБ, TasksMax=64, Nice=10 и таймаутом до 10 минут; на cgroup v1
используй также MemoryLimit=1G. Анализ и рендер идут последовательно, по одной песне.
Исходники ограничены суммой 256 МБ, рендер — максимум 12 композициями.

После анализа создаётся `analysis/<md5>.json`. Выбери варианты фрагментов в `plan.json`:

```json
{"tracks": [{"md5": "…", "targetBpm": 126, "segment": 0}, {"md5": "…", "targetBpm": 126, "segment": 1}]}
```

`md5` берётся из `sources.json`, `segment` — индекс в `segments` результата анализа.
Одинаковый `targetBpm` у соседей включает сведение в ритм. Разный — короткую смену.
После прослушивания можно задать в записи `sourceStart`, `sourceEnd` и исходный
`sourceBpm`: это сохраняет окончание вокальной фразы, даже если оно выходит за
автоматическую сетку. `transitionBeats` у входящей песни меняет длину сведения.
Ручные границы пользователя по-прежнему ограничивают такой исправленный фрагмент.
Полный микс, файл переходов и `tracklist.txt` можно отправить владельцу для оценки;
не добавляй их автоматически в общую разметку или плейлисты.

Для повторной сборки сохраняются исходники, варианты фрагментов и план. После оценки
временные PCM-клипы и отдельное окружение можно убрать по их конкретным путям.

## Воспроизведение в Android 0.15.1

В плейлисте открой «Воспроизведение». Режим запоминается отдельно для каждого
плейлиста на устройстве; сервер хранит общую разметку аудио по MD5 оригинала.

- «Обычное» играет выбранные песни целиком или по сохранённому вручную фрагменту.
- «Плавное» уменьшает громкость в конце и увеличивает в начале следующей песни.
- «DJ» использует подготовленные фрагменты примерно по 80 / 110 / 140 секунд.
  Подходящие границы фразы важнее заданной длины; фрагмент может начинаться
  с активной середины композиции, если есть подтверждённая граница входа.
- «DJ: ремикс» подбирает фрагменты под ползунок 10–120 секунд с допуском около
  трёх секунд. Выбирает следующую
  песню из ближайших 1–50 песен (по умолчанию 10), с учётом её места и близости
  темпа. К прежней песне можно вернуться за другим фрагментом; после максимум
  1–10 использованных фрагментов (по умолчанию 3)
  фрагментов либо исчерпания вариантов она уходит из очереди. Обычный скип
  убирает её сразу. Меняется только очередь воспроизведения, состав плейлиста
  и исходные файлы сохраняются. Повтор очереди в этом режиме отключён.

«Слушать ремикс» в настройках запускает подборку уже подготовленных для него
песен. Можно также использовать «Только DJ» в списке: в режиме ремикса фильтр
отбирает песни с найденными границами выбранной длины. Если подходящей пары нет,
Android 0.15.1 использует запасной отрезок приблизительно выбранной длины с
мягким переходом. Вход берётся из доступных точек либо с исходного начала,
конец ограничивается длительностью. Подпись «примерный переход» отличает его от
найденных границ: целостность слов здесь не подтверждена. В Android 0.17.0 ручной
диапазон ограничивает допустимую область: ремикс выбирает короткие куски внутри
неё, сохраняя обрезанные пользователем вступление и хвост за пределами воспроизведения.
«Доиграть полностью» играет весь ручной диапазон.

В обычном DJ есть переключатель «Только переходы»: первая песня начинает играть
примерно за десять секунд до своего перехода. После входа следующей играет её
начало, затем плеер перематывает к последним десяти секундам фрагмента. Это режим
прослушивания стыков, поэтому перемотка между соседними стыками ожидаема.

Большая декоративная обложка из полного плеера убрана, транспорт расположен
перед оценками и дополнительными действиями. Под настройками появляется
«Обновить», только если сервер сообщил о более новой APK. Проверка выполняется
при открытии/возвращении в приложение, не чаще раза в пять минут; повторный
таймер при открытом приложении — раз в пятнадцать минут. Ошибка проверки релиза
не меняет состояние сети музыкального плеера. Установка запускается нажатием.

## Переходы и сохранённые файлы

Плеер использует два MediaPlayer и прежние оригиналы с телефона либо сетевой
поток. Подготовка DJ не скачивает музыку на телефон повторно. В обычном DJ ручной
фрагмент приоритетнее автоматического; в ремиксе он ограничивает область выбора.
«Доиграть полностью» отменяет DJ-фрагмент
только у текущего элемента очереди. Скип и управление с экрана блокировки работают
во всех режимах; очередь ремикса продолжает двигаться и при свёрнутом приложении.

Совместимые темпы подстраиваются максимум на 3%. Следующая песня входит тихо,
а предыдущая сохраняет громкость до границы последнего распознанного слова.
Затем предыдущая затихает внутри найденной паузы. Без подходящего общего темпа
сохраняются разные темпы и выполняется наложение без обещания точного beatmatch.
Точность запуска MediaPlayer ограничена, в частности, таймером примерно 50 мс.

Отсутствие DJ-разметки у следующей песни не отменяет фрагмент предыдущей:
следующая может входить со своего обычного начала. Если не успела загрузиться
сама аудиодорожка, текущая завершается на своей границе, затем плеер ждёт
готовности следующей. Сеть всё ещё может вызвать паузу; плеер не продлевает
текущий фрагмент до конца оригинала и не начинает его заново.

## Подготовка и очередь работ

`POST /api/dj` — владельческий запрос текущей и ближайших песен, максимум десять
активных работ вместе с уже начатой. Сервер ограничивает и запросы старых APK,
которые присылали весь плейлист. При смене окна отменяются ещё не начатые задачи
за его пределами; готовые результаты и числовой кеш сохраняются. Открытие
настроек не ставит плейлист на обработку. NativeInbox обновляет окно и в фоне
по сохранённой Android-очереди, без дополнительных загрузок аудио на телефон.

В строках видны готовые фрагменты и песня, которую действительно обрабатывают.
Ожидающие песни не помечаются повсеместной подписью «DJ в очереди». Название
текущей работы и состояние worker доступны в настройках и очереди. `dj_runtime`
хранит heartbeat, `dj_priority` — временное окно работ; обе таблицы не входят
в резервную копию. Счётчик обработанных песен означает готовый анализ, который
может и не найти подходящих границ, а не гарантированное наличие фрагмента.

`aidj.dj_worker` последовательно скачивает с Диска один оригинал, проверяет MD5,
оценивает ритм и энергию, затем проверяет границы вокальных фраз локальной
CPU-моделью faster-whisper (`base`, int8). Сначала используются уже сохранённые
числовые результаты. При необходимости распознаются короткие участки около
перспективных границ, без многократного перебора температур декодирования.
Тексты не сохраняются и LLM/API для анализа не вызывается.

Промежуток между словами считается пригодным только внутри фактически
проанализированного окна. Неразборчивые слова занимают своё время; отсутствие
распознавания не считается паузой. Начало из середины разрешено только при
проверенной границе входа (`entryVerified`). Это автоматическая проверка условий,
не прослушивание человеком: распознавание пения по-прежнему может ошибиться.
Если подтверждения нет, сохраняется начало оригинала или полный трек.

`dj_analysis` хранит небольшую разметку по MD5; `dj_evidence` — только числовые
времена слов, уверенность, покрытие анализа и музыкальные признаки. Обе таблицы
входят в часовой бэкап на Яндекс Диск. В каталог выдаются лишь варианты фрагментов,
не слова или весь кеш. `djV3` читается APK 0.13.0; `djV2` сохраняет варианты
с начала для APK 0.12.1, а старое `dj` также исключает короткие затухания,
которые APK 0.12.0 не умеет безопасно совмещать с ранним входом следующей песни.

## Установка необязательного worker

После обычной настройки сервера:

```bash
python3 -m venv .dj-venv
.dj-venv/bin/pip install -r requirements-dj-runtime.txt
sudo .venv/bin/python deploy/install_services.py --user music --install
sudo systemctl enable --now aidj-dj-prepare.service
```

Модели находятся в `$AIDJ_STATE_DIR/dj-models` и могут быть скачаны заново.
Установщик не включает этот сервис автоматически. Worker обрабатывает одну
песню за раз, удаляет временную копию и завершает дочерний процесс для освобождения
памяти модели/декодера. Исходники ограничены 40 МБ / 10 минут. В unit заданы
MemoryMax/MemoryLimit=1G, TasksMax=64, Nice=10 и низкий приоритет I/O; на cgroup v1
MemoryLimit обеспечивает фактический предел. На время тяжёлых сборок сервис
останавливают. После превышения лимита памяти автоматического перезапуска нет:
сначала требуется диагностика. Анализ не блокирует редактирование плейлистов,
не меняет оценки и не создаёт доставок песен в приложение.


## Больше вариантов в 0.13.1

`djV4` содержит до 32 кандидатов ремикса на песню. Входы и выходы формируются
из фактически наблюдавшихся пауз между уверенно распознанными словами, а не
из случайного таймера. Пул распределён по времени песни и диапазонам длины.
Плеер подбирает вариант под соседнюю песню и избегает перекрытия с уже
услышанными фрагментами. В очереди по-прежнему одна запись на исходную песню;
максимум три возвращения/посещения и явный скип ограничивают сессию.

Для размеченных границ допустимо более короткое финальное затухание:
0,25 с для обычного DJ, 0,15 с для ремикса. Полная громкость предыдущей
песни удерживается до границы после слова, вход следующей занимает минимум
1,5 секунды. Это автоматическая проверка таймкодов, не гарантия слуховой оценки.
`djV3`, `djV2` и `dj` фильтруются для прежних APK; их готовые варианты сохраняются.

Разметка пересчитывается из числового кеша. Уже запущенный на Mac полный проход
продолжает работать без обновления или повторного скачивания песни. Для большой
очереди варианты передаются компактными числовыми массивами `remixPool`, чтобы
сотни песен с десятками вариантов не дублировали большие JSON-объекты.


## Опорные точки и длительность в 0.14.0

В настройках DJ-ремикса есть ползунок от 10 секунд до 2 минут. Это длительность
одного фрагмента, отдельно от времени смешивания. Плеер ищет пару вход/выход
рядом с выбранной длительностью (обычно в пределах трёх секунд), учитывает темп,
энергию соседних песен и уже звучавшие участки. Текущая песня и уже загруженное
начало следующей сохраняют свои границы при изменении настройки.

Вместо хранения всех сочетаний отрезков `djV4.anchors` содержит до 256 входов
и 256 выходов на песню. Границы по словам требуют наблюдавшейся паузы, уверенных
соседних слов и запаса с обеих сторон. Неудачное первое распознавание повторяется
на небольших смещённых окнах. `boundaryPass` отмечает завершённый дополнительный
проход, чтобы подготовка не повторялась бесконечно.

Второй путь — `acousticAnchors`: точки по измеренным спадам энергии звука,
с учётом известных слов и музыкального ритма. Это менее уверенные варианты;
у них `quality: acoustic`, `needsReview: true`, без поддельной отметки
`wordGuarded`. Они показываются как «по звуку, проверить». Если подходящий
короткий фрагмент всё ещё не найден, песня остаётся в очереди как исходный полный
трек с явной отметкой для проверки; отсутствие результата не скрывает песню.

Подборка «DJ — проверить переходы» собирает сложные песни автоматически в
приложении. Она не копирует музыку на Диск, не создаёт доставок на телефон и
не меняет общий плейлист. Там можно слушать ремикс или открыть существующий
редактор фрагмента и проверить конкретные границы вручную.

В очереди точки передаются компактно с точностью до миллисекунд. Секундный
статус плеера и сохранение позиции не дублируют эти массивы: интерфейс берёт их
из локального каталога. Большая очередь не передаётся через Android Intent,
чтобы не упираться в лимит Binder.


## Очередь и громкость в Android 0.17.0

Будущие песни переносятся долгим нажатием; короткий свайп прокручивает список.
Поиск проверяет всю очередь, включая ещё не показанные строки. Двойная стрелка
ставит найденный элемент следующим после текущего и имеет приоритет над
автоматическим выбором DJ. Крестик удаляет только этот элемент очереди.
Строка `1 · 2:09–2:22` в ремиксе показывает номер будущего фрагмента в ориентировочном
плане и его интервал без долей секунды. `—` означает, что фрагмент пока за пределами рассчитанного плана;
порядок и будущие варианты могут обновиться по мере воспроизведения. Оценки
доступны в библиотеке и карточке песни, а в очереди не дублируются.

Измеренные уровни громкости хранятся по MD5 в `audio_loudness`. При простое
существующий последовательный DJ-worker измеряет следующий оригинал через
FFmpeg loudnorm, сохраняет только входные LUFS/true peak и удаляет временную
копию. При новом DJ-анализе используется уже загруженный оригинал. Ошибки
измерения имеют отложенный повтор; неизвестная громкость не оценивается по
нормированной DJ-огибающей и не меняет усиление. Снимки БД сохраняют измерения.

Плеер стремится к −16 LUFS с мягким ограничением поправки ±6 dB и мёртвой зоной
1.5 LU. Измеренный true peak после поправки не должен превышать −1 dBTP;
это ограничение приоритетнее мягкого лимита. Поправка постоянна для песни,
накладывается поверх существующей огибающей перехода и не переписывает аудио.
Положительная поправка использует отдельный
[LoudnessEnhancer](https://developer.android.com/reference/android/media/audiofx/LoudnessEnhancer)
каждого MediaPlayer, отрицательная — его громкость. Если эффект недоступен на
устройстве, усиление пропускается; ослабление продолжает работать.

Android 0.17.2 рассчитывает ближайшие десять будущих фрагментов через тот же
`RemixPlan`, который управляет реальным переходом. План строится на отдельной
копии приватной очереди в фоновом потоке; его расчёт не вызывает MediaPlayer
и не меняет состояние воспроизведения. Повторные появления одного элемента
получают отдельные номера и интервалы. Текущий кусок исключён из нумерации
будущих; его поздние возвраты показаны под ним. Порядок строк остаётся
приоритетом очереди, а номера показывают рассчитанный порядок фрагментов.
Скип, удаление, перестановка и настройки делают план неактуальным и вызывают
пересчёт; устаревшие снимки не размечают новую очередь.

При обновлении очереди темп больше не назначается повторно без изменения.
Назначение нового темпа выполняется при заглушённом проигрывателе, с сохранением
намерения пользователя оставаться на паузе. Это необходимо, поскольку
[`setPlaybackParams`](https://developer.android.com/reference/android/media/MediaPlayer#setPlaybackParams(android.media.PlaybackParams))
у подготовленного MediaPlayer с ненулевой скоростью может запускать проигрывание.
