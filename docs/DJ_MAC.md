# Полная подготовка DJ на Mac

На Mac используется уже настроенный SSH-доступ к серверу. Ключи Telegram,
Яндекс Диска и cookies остаются на VM. Mac получает одну песню на каждый рабочий
процесс, проверяет её размер и MD5, анализирует весь файл и возвращает числовую
разметку. Оригинал на Mac удаляется после задания; готовые фрагменты появляются
в том же приложении, без новой APK и повторного скачивания музыки на телефон.

## Первый запуск

В обычном терминале Mac, вне SSH-сессии VM:

```bash
git clone https://github.com/Ilya1510/aidj-codex-music.git ~/aidj-codex-music
cd ~/aidj-codex-music
bash scripts/dj-mac.sh --workers 4
```

Если копия проекта уже есть, вместо `git clone` выполни в её папке
`git pull --ff-only`. Скрипт находит Python 3.12, при наличии Homebrew может
установить `python@3.12`, создаёт отдельное `.dj-mac-venv` и ставит закреплённые
зависимости. При изменении файла зависимостей окружение обновляется. Если нет
ни Python 3.12, ни Homebrew, скрипт останавливается с понятной инструкцией.

Для окружения, модели и рабочих файлов нужно хотя бы 3 ГБ свободного диска.
Перед запуском показываются ресурсы Mac. Модель загружается один раз; затем
несколько CPU-процессов используют общий кеш. GPU в этом варианте не требуется
и специально не включается.

По умолчанию сервер — SSH-псевдоним `ilya-grid-vm`. Если обычный
`ssh ilya-grid-vm` ещё не работает, сначала настрой этот доступ. Проверки ключа
сервера не отключаются. Другие адрес и путь задаются явно:

```bash
bash scripts/dj-mac.sh --server user@host --remote-project /home/user/aidj-codex-music --workers 4
```

Клиент не обновляет и не перезапускает сервер самостоятельно.

## Пробный запуск и продолжение

```bash
bash scripts/dj-mac.sh --workers 1 --limit 1
bash scripts/dj-mac.sh --workers 4
```

Первый вызов обработает не больше одной песни; второй продолжит ту же массовую
подготовку. Уже завершённый полный анализ повторно не выполняется. Можно
ограничить задание одним плейлистом:

```bash
bash scripts/dj-mac.sh --playlist Volleyball --workers 4
```

Каждый процесс получает отдельную песню через серверную аренду задания.
Несколько Mac могут участвовать одновременно: активные задания не выдаются
другому клиенту, подтверждение готового результата допускает безопасный повтор.
Разрыв соединения или перезапуск не теряет уже записанные результаты. После аварийного отключения аренда истекает максимум через пять минут; при работающем клиенте она продлевается каждые 30 секунд.

`Ctrl+C` останавливает процессы и освобождает задания. Частичная числовая
разметка остаётся в локальном checkpoint и используется при продолжении.
Прогресс выводится по готовым песням, а не по каждому аудиофрагменту. Тексты
распознавания и содержимое SSH-ошибок в вывод не попадают.

Скрипт запускается через `caffeinate -i`: блокировка экрана не должна усыплять
Mac во время задания. Закрытие крышки всё ещё может вызвать сон; после него
достаточно повторить команду.

## Ограничения ресурсов и качества

`--workers` — число песен, которые обрабатываются одновременно, от 1 до 8.
По умолчанию берётся не больше четырёх, с уменьшением по CPU и объёму RAM.
`--threads` задаёт CPU-потоки одного анализатора; по умолчанию один. Например,
`--workers 4 --threads 1` — четыре песни одновременно, а не четыре процесса,
каждый из которых занимает все ядра.

Один анализ ограничен пятнадцатью минутами и суммарным RSS своего дерева
процессов в 1 ГиБ. При превышении лимита собственная группа процессов
останавливается, повтор с увеличенным лимитом автоматически не запускается.
Временные файлы обрабатываются потоково; одновременно хранятся оригиналы
только активных заданий, до 40 МБ на песню.

Полный проход ищет больше пригодных мест, чем обычная подготовка ближайшей
десятки. Это не гарантирует подходящую короткую фразу у каждой песни: если
распознавание не даёт надёжных границ, готовый анализ может остаться без
автофрагмента. Более мощный CPU ускоряет проверку, но сам по себе не улучшает
качество распознавания пения.
