# Восстановление после потери VM

## Что должно пережить сервер

1. Этот GitHub-репозиторий — код и инструкции.
2. Яндекс Диск — сама музыка и `/Музыка/_aidj_state/` с резервными копиями данных.
3. Отдельная приватная копия OAuth/токена Telegram и каталога `android-signing/`.
   Токены можно получить заново; потерянный ключ подписи APK восстановить нельзя.

На Диске сохраняются плейлисты и порядок, алиасы, оценки и авторы, предложения,
настройки фрагментов, метаданные библиотеки и очереди подтверждений. Не сохраняются
OAuth, cookies, ключ APK, браузерные сессии, одноразовые коды входа, ключи переноса
между Mini App и Android, незавершённые поисковые задания и временные файлы.

## Последовательность

1. Подготовь нового пользователя, clone, `.venv` и runtime-инструменты по
   [SETUP.md](SETUP.md), **пока не включай службы**.
2. Верни доступ к **тому же Яндекс Диску** через `connect_yandex.py --disk`.
3. Восстанови рабочую базу в пустой каталог:

   ```bash
   .venv/bin/python -m aidj.backup restore
   ```

   Помощник скачивает снимок по манифесту, проверяет размер, MD5, SHA-256 и
   целостность SQLite. Существующую базу он не перезаписывает.
4. Верни остальные подключения: Музыку, cookies YouTube и **прежний бот Telegram**.
   Для приватных файлов — права 0600, каталоги — 0700; владелец — пользователь службы.
   Восстановленный `owner_id` сохраняет права владельца. Новую привязку через
   `/start` постороннему человеку выдавать не нужно.
5. Верни прежний `android-signing/` из приватной копии и сохранённые APK, если они есть.
   При отсутствии APK их можно собрать заново с прежним ключом. Нельзя публиковать
   другие байты под номером уже выпущенной версии: увеличь `versionCode`/`versionName`.
6. Настрой тот же стабильный HTTPS-домен либо новый туннель, установи службы.
7. Открой `/app`, `/reviewstats`, `/suggestions`, проверь несколько песен и участников.
   Запусти резервное копирование вручную и убедись, что timer включён:

   ```bash
   sudo systemctl start aidj-state-backup.service
   systemctl status aidj-state-backup.timer
   ```

## Если нужно откатиться на дневной снимок

Два последних состояния лежат в `state-a.sqlite` и `state-b.sqlite`; указатель —
`latest.json`. Дневные копии — семь вращающихся слотов `daily-0.sqlite` … `daily-6.sqlite`
(понедельник — 0, воскресенье — 6). Снимок делается при первом успешном запуске
копирования за день по московскому времени. До публикации манифеста новая копия
проверяется; прерванная отправка не заменяет предыдущий указатель.

Для проверки старой копии используй отдельную пустую папку, а не рабочую базу:

```bash
.venv/bin/python -m aidj.backup restore --day 0 --to /tmp/aidj-restore-check
```

Для замены рабочей базы сначала останови **все** `aidj-*` службы и таймеры,
сохрани текущую папку состояния в приватное место и восстанови в пустой каталог.
Не копируй один `bot.sqlite` поверх работающего SQLite с оставшимися `-wal`/`-shm`.

## Что будет на телефоне

Обновление APK с прежними package name и ключом сохраняет локальные файлы.
Если изменился адрес сервера, заново открой «Подключить приложение» через своего
бота. Одноразовые ссылки и web-сессии специально не восстанавливаются из бэкапа.

Кеш браузерного Mini App привязан к HTTPS-домену. При новом домене прежний кеш
может стать недоступен; песни остаются на Диске и их можно загрузить снова.
Телефонный Android-кеш не является серверной резервной копией.
