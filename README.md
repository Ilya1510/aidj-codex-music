# AI DJ · Codex Music

Личный музыкальный сервер: Telegram-бот, Android-плеер и Telegram Mini App.
Музыкальные файлы хранятся **на Яндекс Диске**; сервер ищет записи, готовит аудио,
управляет плейлистами и собирает оценки. Android умеет слушать скачанное без сети,
играть при заблокированном экране и показывать очередь.

Репозиторий содержит исходники и инструкции. Токены, cookies, база с оценками,
музыка, ключ подписи Android и APK в Git не включены.

## Что умеет

- Поиск песни по названию или ссылке: Яндекс Музыка, затем YouTube.
- Прослушивание и выбор записи, добавление в плейлисты, отдельные фрагменты.
- Общая библиотека бота и приложения; загрузка на телефон по явному нажатию.
- Тихая фоновая загрузка плейлиста с одним уведомлением, общим прогрессом,
  автоматическими повторами и докачкой после обрыва сети.
- Очередь, шафл, повтор, обычные и плавные переходы между песнями.
- Разметка друзьями в Telegram: 👍 / 👎 / «Всё равно»; один голос человека на песню.
- Предложения после предпрослушивания и подтверждения автора. Они сохраняются
  в «Предложку», но автоматически на телефон **не скачиваются**.
- Владелец принимает предложения в общий Volleyball; автору приходит поздравление.
- При удалении песни из Volleyball уведомление получают поставившие ей дизлайк.
- В разметке песни с дизлайками получают небольшой приоритет для перепроверки.
- В приложении: участники, сортировки, фильтр по балансу лайков и дизлайков,
  число песен после фильтрации, голосование без сети.
- Точные фильтры по участникам: кто лайкнул, дизлайкнул, выбрал «всё равно»
  или ещё не оценил; сочетание всех/любого условия, поиск по имени и нику.
- Режим «По важности»: люди перетаскиваются в нужный порядок, первая оценка
  👍/👎 определяет итог песни; по умолчанию остаются только итоговые лайки.
- Резервные копии плейлистов, оценок и предложений на Диске; ежедневная проверка YouTube.

Владелец управляет библиотекой и приложением. Друзья могут только слушать,
оценивать и предлагать записи; им недоступны Диск, приложение владельца и чужие оценки.

## Где что находится

| Данные | Место |
| --- | --- |
| Песни и M3U8 плейлистов | Яндекс Диск: `/Музыка/<название плейлиста>/` |
| Подготовленная библиотека | Диск: `/Музыка/aidj_codex_music/` |
| Подтверждённые предложения | Диск: `/Музыка/Предложка/` |
| Архивы и исходники | Служебные папки `/Музыка/_aidj_*`; вне папок плейлистов |
| Резервные копии данных | Диск: `/Музыка/_aidj_state/` — текущий, предыдущий и 7 дневных снимков |
| Рабочая БД, оценки, каталоги | Сервер: `~/.local/share/aidj-codex-music/bot.sqlite` |
| Настройки Telegram и адрес сервера | Сервер: та же папка, `telegram.json`, `miniapp-url.json` |
| OAuth и cookies источников | Сервер: `~/.local/share/yandex-music-export/` |
| Ключ и пароль подписи APK | Сервер: `~/.local/share/aidj-codex-music/android-signing/` — сохранять отдельно |
| APK и инструменты сборки | Сервер: `android-release/`, `android-build/`, `android-tools/` в папке состояния |
| Офлайн-музыка Android | На телефоне, отдельно от сервера и кеша Telegram Mini App |

База на VM — рабочая копия для быстрых запросов. Служба резервного копирования
проверяет изменения раз в час и публикует снимок на Диск. Если обрабатывается
песня или Диск недоступен, копирование откладывается; до успешной записи сохраняется
предыдущий снимок. При потере VM восстанавливается последнее успешно сохранённое состояние.

**Одного GitHub недостаточно для восстановления данных.** Нужны резервная копия
с Диска и повторный вход в сервисы. Для обновлений уже установленной APK обязательно
нужен прежний ключ подписи. Автобэкап данных не содержит OAuth, cookies, сессий и ключа APK.

## Запуск и восстановление

- **[Новый сервер](docs/SETUP.md)** — окружение, вход в сервисы, systemd и HTTPS.
- **[Восстановление после потери VM](docs/RECOVERY.md)** — вернуть плейлисты и оценки с Диска.
- **[Как всё работает](docs/ARCHITECTURE.md)** — компоненты и путь песни/голоса.
- **[Обслуживание](docs/OPERATIONS.md)** — проверки, бэкапы, обновления и сборка APK.
- **[Пробный DJ-микс](docs/DJ_PREVIEW.md)** — отдельная лаборатория фрагментов и сведений для прослушивания.

Основная платформа сервера и сборки Android: Ubuntu 24.04, Linux x86_64, Python 3.12.
Зависимости закреплены в `requirements.txt`; Node нужен загрузчику YouTube.

## Структура

```text
aidj/                 бот, API, каталог, оценки, фоновые задания и резервные копии
miniapp/              общий интерфейс Mini App и встроенного Android WebView
android/              Android-плеер, фоновые загрузки, сборка и публикация APK
deploy/               установщики и шаблоны systemd
scripts/              проверка состава перед публикацией
tests/                Python, Node, браузерные и JVM-проверки
docs/                 установка, восстановление, устройство и обслуживание
connect_*.py          скрытый локальный ввод токенов и cookies
```

## Проверки

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
node --test tests/*.test.mjs
```

Браузерные проверки требуют Playwright и Chromium, описаны в
[обслуживании](docs/OPERATIONS.md). JVM-проверки загрузчика используют JDK и локальный HTTP-сервер с тестовыми байтами;
зависимость JSON закреплена по SHA-256. Реальные загрузки музыки в unit-тестах
заменены фикстурами; токены для них не нужны.

DJ-режим Android: настройки отдельного плейлиста, подготовка фрагментов, офлайн и ограничения — [docs/DJ_PREVIEW.md](docs/DJ_PREVIEW.md). Для фонового анализа есть отдельное необязательное CPU-окружение и ограниченный systemd-сервис.

Android 0.13.0 добавляет отдельный «DJ: ремикс» с короткими фрагментами и возвратами,
прослушивание только переходов, компактный плеер и ненавязчивую отметку обновления.
Подготовка ограничена текущей и ближайшими песнями (не более десяти активных работ);
готовые результаты сохраняются. Подробности и ограничения — в описании DJ выше.

Для массового полного анализа всей библиотеки на Mac: [команда запуска и продолжение](docs/DJ_MAC.md). По умолчанию четыре процесса по одному CPU-потоку, готовые результаты возвращаются на сервер через существующий SSH.

Android 0.13.1 расширяет пул ремикса до 32 вариантов на песню и выбирает их по энергии, длине и уже звучавшим участкам. Более короткое финальное затухание допускается только при сохранённых запасах вокруг распознанных слов; данные для старых APK фильтруются отдельно.
